# macos-mscp-scan v0.4.0

This release refines the default `personal` baseline after an end-to-end review
on a personally administered Mac. It reduces organization-specific noise,
checks more effective local state, and fixes result-contract mismatches that
could misclassify a passing check as a finding.

## Included

- traditional `auditd`, install/sudo forensic logging, global CIS password
  policy, fixed organization time-server and selected privacy-choice controls
  are explicitly outside the default personal scope;
- cross-user screen-unlock authorization and mandatory user-name entry at the
  login window are outside the default single-user personal threat model;
- App Store updates, Terminal Secure Keyboard Entry, Bluetooth Sharing,
  password hints, Remote Apple Events and SMB use effective active-user or
  listening-port checks;
- Firewall Block All is accepted as an enabled firewall state;
- screen-lock checks run in the active user's context;
- a sudo credential-cache timeout from zero through two minutes passes, which
  permits short administrative workflows without leaving a long reuse window;
  and
- generated numeric result contracts are validated for customized sudo,
  Bluetooth Sharing, password-hint, Remote Apple Events and SMB checks.

The `personal` profile remains a security-posture audit, not a CIS Benchmark
assessment. Excluded rules are outside scope, not passes. Use unchanged
`cis_lvl1` or `cis_lvl2` when the question is formal CIS compliance or centrally
enforced configuration.

## Validation

The release passed shell syntax checks, interface tests and a full mSCP
preparation smoke test. A user-authorized read-only audit on macOS 26 Apple
Silicon completed with 48 applicable checks passed, zero findings and one
architecture-appropriate `N/A` for Power Nap.

## Compatibility

macOS 14 Sonoma, 15 Sequoia, and 26 Tahoe are supported on Apple Silicon and
Intel. The full privileged validation audit was run on macOS 26 Apple Silicon.

## Safety contract

The generated mSCP audit is invoked only with `--check`; the wrapper never uses
`--fix` or `--cfc`. An AI agent may prepare a run but must stop before the
interactive audit. Only the user reviews the prompt and authorizes macOS
administrator authentication in their normal Terminal.

## Download and verify

The release-signing key fingerprint is:

```text
SHA256:Rt9xlHKnOMVeREiwG041268qY0kxu72vYVt+CntuF+4
```

Download the four release assets, verify the SHA-256 manifest and its detached
SSH signature, then extract the source archive:

```zsh
set -e
release_dir="$(mktemp -d /private/tmp/macos-mscp-scan-v0.4.0.XXXXXX)"
cd "$release_dir"

curl -fLO https://github.com/r4kh1m/macos-mscp-scan/releases/download/v0.4.0/macos-mscp-scan-v0.4.0.tar.gz
curl -fLO https://github.com/r4kh1m/macos-mscp-scan/releases/download/v0.4.0/SHA256SUMS
curl -fLO https://github.com/r4kh1m/macos-mscp-scan/releases/download/v0.4.0/SHA256SUMS.sig
curl -fLO https://github.com/r4kh1m/macos-mscp-scan/releases/download/v0.4.0/r4kh1m-release-signing-key.pub

shasum -a 256 -c SHA256SUMS
{
  printf 'r4kh1m-release namespaces="file" '
  cat r4kh1m-release-signing-key.pub
} > allowed_signers
ssh-keygen -Y verify \
  -f allowed_signers \
  -I r4kh1m-release \
  -n file \
  -s SHA256SUMS.sig < SHA256SUMS

tar -xzf macos-mscp-scan-v0.4.0.tar.gz
cd macos-mscp-scan-v0.4.0
```

To use an AI agent, give it the extracted directory and ask it to follow
`AGENTS.md`. To prepare the scan yourself:

```zsh
zsh ./scan_cis.zsh
```

The script stops after preparation and prints the one `--run-prepared` command
that the user must run in a normal interactive Terminal.
